# 26H 手动比赛计时器设计

## 背景

当前固件入口运行的是 25H 任务，并在 OLED 首行显示 MPU6050 的 Z 轴航向角。2026 年 H 题要求按键启动时开始计时并显示时间，要求 2 的正式终点是小车顺时针行驶一圈、停回 A 点后停止计时。

本阶段只实现可独立验证的第一版：车辆保持静止，KEY1 手动切换计时开始和停止。后续版本再让同一个启动事件同步启动巡线，并用 A 点检测替代手动停止。

## 目标

- 新建独立的 `Accomplish/26H.c` 和 `Accomplish/26H.h`，不修改或复用 25H 的任务流程。
- KEY1 第一次按下时清零并开始计时，第二次按下时停止并冻结结果，再次按下时清零并开始新一轮。
- 使用 100 Hz 系统节拍进行整数计时，分辨率为 10 ms。
- 在 OLED 原 `Z:` 所在的首行显示时间，例如 `T:12.34s`。
- 停止正常启动流程中的 MPU6050 初始化、校准和周期更新。
- 第一版不发出任何车辆运动命令。
- 所有操作和提交只保留在本地，不访问或更新远端仓库。

## 非目标

- 本阶段不实现自动识别 A 点、自动停车或一圈完成判定。
- 本阶段不实现 26H 体育场形黑线的巡线速度与终点制动控制。
- 不删除 Heading、MPU6050、25H 或现有航向运动控制源码，以便其他任务继续参考或后续按需恢复。
- 不改动 KEY2 的物理急停行为。

## 架构

### 26H 控制器

`Accomplish/26H.c` 作为本题唯一的任务控制器，保存计时运行状态和累计节拍。公开接口为：

```c
void Accomplish26H_Init(void);
void Accomplish26H_Update(const App_UpdateContext_t *context);
uint8_t Accomplish26H_IsTiming(void);
uint32_t Accomplish26H_GetElapsedTicks(void);
```

`main.c` 在 `App_Init()` 之后初始化 26H 控制器，并在每次有效的 `App_Update()` 后调用 `Accomplish26H_Update()`。它不再初始化或更新 25H Mission，因此 KEY1 不会意外启动旧任务。

这种边界让后续版本可以在 26H 控制器的开始分支中启动巡线，在停止分支中停车，而不需要改变计时接口或 OLED 显示接口。

### 计时状态

内部使用 `uint32_t` 保存累计系统节拍，不累计浮点秒数。运行时按 `context->elapsedTicks` 累加，并在接近 `UINT32_MAX` 时饱和，避免长时间运行后回绕。

只处理 `pressedEdges` 中的 KEY1 位，因此长按不会重复切换：

1. 停止状态收到 KEY1 按下沿：累计值清零，进入运行状态；当前更新批次不计入新一轮。
2. 运行状态每次更新：先累计本批实际经过的节拍。
3. 运行状态收到 KEY1 按下沿：累计本批节拍后进入停止状态并冻结结果。
4. 停止状态的普通更新不改变累计值。

在主循环正常以 100 Hz 运行时，手动按键边界的量化误差不超过一个节拍，即 10 ms。

### OLED 显示

`DebugDisplay.c` 移除首行对 Heading 的读取，改为读取 `Accomplish26H_GetElapsedTicks()`，按 `TICK_HZ` 换算为秒并显示两位小数。运行和停止状态都显示累计值，停止后画面保持最终成绩。

OLED 仍按现有 10 个系统节拍刷新一次，即画面约每 100 ms 更新；计时数据自身仍保持 10 ms 分辨率。

### 停用 MPU6050

`App.c` 不再调用 `Heading_Init()`、`Heading_Calibrate()` 或 `Heading_Update()`，也不再显示开机航向校准页面。这样正常启动和主循环都不会访问 MPU6050 软件 I2C。

Heading 和 MPU6050 源文件继续保留。Telemetry 或参数模块读取未初始化的 Heading 状态时只会得到离线状态，不会主动访问硬件。

## 数据流

```text
Tick_PollCount + Key_GetPressedMask
              |
              v
      App_UpdateContext
              |
              v
   Accomplish26H_Update
       |              |
       | KEY1 edge    | elapsedTicks
       v              v
   running flag   elapsed tick count
              |
              v
 DebugDisplay_Update -> T:12.34s
```

## 测试

新增宿主测试 `tests/host/test_26h.c`，直接测试 26H 控制器，不依赖 GPIO、Tick 中断或 OLED 桩件。测试覆盖：

- 初始化后停止且时间为零。
- 第一次 KEY1 按下沿清零并开始。
- 单节拍和一次补多个节拍时均精确累计。
- 长按但没有新按下沿时不重复切换。
- 第二次 KEY1 按下沿停止并冻结。
- 停止后的更新不再累计。
- 再次按下 KEY1 清零并开始新一轮。
- 空上下文不改变状态。

测试先以缺少 26H 实现的预期原因失败，再添加最小实现使其通过。随后运行全部宿主测试、目标工程构建检查和 `git diff --check`。

## 验收标准

- 上电不出现 MPU6050 校准页面，也不进行 MPU6050 初始化、校准或周期读取。
- OLED 首行显示 `T:` 时间，不再显示 `Z:` 航向。
- 第一次按 KEY1 后时间从零开始增长，第二次按 KEY1 后时间保持不变，第三次按 KEY1 后从零开始新一轮。
- 第一版按 KEY1 不会启动电机，车辆保持静止。
- 25H 源文件保持不变。
- 新增宿主测试和现有测试全部通过，目标固件可成功构建。

## 后续扩展

第二版在 26H 控制器的开始事件中同步启动 `MotionManager_StartLine()`，并加入“离开 A 点启停线后才允许完成”的门控。车辆再次检测到 A 点启停线且满足最小行驶时间或里程后，控制器自动停车并冻结同一个累计计时值，取代当前第二次 KEY1 手动停止。
